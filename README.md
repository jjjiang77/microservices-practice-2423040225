# 微服务课程项目


## 一、项目名称

**商小淘 ShangXiaoTao**

浙工商校园二手，小商淘好货。"商小淘"得名于浙工商学生的自称"浙小商"——"商"是浙工商的商，也是做买卖的商；"小淘"是爱淘货的小角色。从学生身份自然过渡到交易动作，自带校园认同感。



## 二、项目简介

商小淘是一个面向高校学生的校园二手交易系统，支持商品发布、分类浏览、即时聊天、订单交易和信用评价等核心功能。与闲鱼等通用平台不同，商小淘聚焦校园场景，通过校园邮箱认证限定同校身份，以面对面交割取代物流邮寄，解决校内二手教材、电瓶车、电子产品等物品的精准匹配与信任交易问题。系统涵盖用户、商品、订单、聊天、评价、管理六大模块，后续将逐步演进数据库持久化、微服务拆分、认证授权、消息系统、事务管理、监控运维和容器化部署。



## 三、业务背景

**校内大件物品难寻**：闲鱼搜索"二手电瓶车"匹配结果分散在校外，校内沟通成本高。商小淘限定校园范围内发布与搜索，结果精准聚焦同校。

**二手教材价格偏高**：浙工商书店二手教材定价不透明，缺少议价空间。商小淘让学生自主定价、即时协商，价格灵活透明。

**信任与安全**：校外交易风险高，身份难以验证。商小淘通过校园邮箱认证和信用评价体系，确保同校身份可信。

**交割不便**：校外交易需跨区域邮寄或面交，成本高。商小淘校内面对面交割，零物流成本。

闲鱼 2024 年已上线"学生鱼"频道攻校园市场，说明赛道被大厂认可，但"学生鱼"只是闲鱼的子频道而非独立品牌，独立校园平台仍有差异化空间。商小淘以浙工商为起点，扎根校园文化，做垂直深耕。



## 项目目标与适用场景

**目标**：学期结束前上线一个可试用的 demo，覆盖用户注册、商品浏览、帖子发布、下单交易、校内小法庭等核心链路。支付环节初期采用模拟支付（线下当面交易为主），后续视商户资质申请情况再对接真实支付网关。

**适用场景**：浙工商校园内的二手物品流转，包括但不限于开学季教材低价获取、毕业季宿舍清仓、日常闲置物品（电瓶车、电子产品、日用品等）快速出手。



## 用户角色

主要用户为**学生群体**，同一学生可同时扮演买家和卖家两种角色，角色可随时互换。

**买家**：有购买需求的学生，核心需求是浏览帖子种草、在交易区直接搜索商品、与卖家沟通、下单支付、安全交割、交易后评价。

**卖家**：有闲置物品出售的学生，核心需求是发布帖子引流、在交易区上架商品、管理上下架、回复咨询、处理订单。

**管理员**：平台运营维护人员，负责商品审核、用户管理、举报处理和数据统计。初期可由开发者兼任。



## 功能模块

商小淘采用"内容引流 + 交易承接"的双区架构，借鉴小红书的内容种草模式和闲鱼的交易闭环，形成校园特色的二手交易生态。

### 1. 帖子发布区（内容引流）

模仿小红书的信息流模式，学生可以发帖分享好物推荐、闲置种草、开箱体验等内容，增加平台流量和用户粘性。帖子支持上传图片、撰写文字描述、添加话题标签。每篇帖子下方可以直接挂载商品链接，看到喜欢的内容可以一键跳转到交易区对应的商品页。这个设计让平台不只是冷冰冰的商品列表，而是有温度的校园内容社区——有人发帖"毕业季清仓宿舍好物"，下面挂着一串商品链接，看帖子的人顺手就能买。帖子互动数据（点赞、收藏、评论）也会影响商品的曝光权重，好内容带动好生意。

### 2. 交易区（商品承接）

商城式的商品列表，按分类分区展示：教材区、电子产品区、日用品区、大件物品区、服饰区等。

想直接买东西的人可以像逛淘宝一样按分类浏览、搜索筛选。每个商品页展示图片、标题、描述、价格、新旧程度、卖家信用分。交易区的商品和帖子区的挂链商品共享同一套商品数据，从帖子点进去和从交易区搜到的是同一个商品页。卖家可以单独在交易区上架商品，也可以先发帖子再挂链接，两条路径都能触达买家。

### 3. 用户模块

支持学号注册验证学生身份，确保同校可信。用户个人资料包括头像、昵称、院系、联系方式。系统根据交易历史和评价自动累计信用分，信用分影响搜索排序和帖子曝光。用户可收藏感兴趣的商品、关注常互动的卖家。

### 4. 订单模块

买家确认购买意向后生成订单，支持线上模拟支付或线下当面支付。订单状态流转：待付款 → 待交割 → 已完成，或待付款/待交割 → 已取消。下单后未交割前可取消。买家和卖家可查看全部历史订单，区分买入和卖出。交割方式为校内面对面交割，零物流成本。

### 5. 聊天模块

买卖双方可基于商品发起一对一即时聊天，聊天中可直接分享商品卡片。沟通记录完整保存，作为交易凭证。双方在聊天中协商交割时间、地点和价格。售后问题也优先通过聊天私下沟通解决，沟通记录留存备查。

### 6. 小法庭模块（纠纷仲裁）

仿照闲鱼小法庭机制，当买卖双方售后协商不成时，可发起校内公开小法庭。发起方提交纠纷描述和证据截图，平台在校内公开展示案件，由同校学生投票仲裁。投票设有时间窗口（如 48 小时），达到一定票数阈值后出裁决结果。小法庭记录纳入双方信用档案，既是纠纷解决机制，也增强了平台的自治氛围和社区参与感。

### 7. 管理模块

管理员负责新发布商品和帖子的合规审核，处理用户举报，管理违规账号，查看平台数据统计（交易量、活跃用户、热门分类、帖子互动量等）。



## 核心业务流程

完整交易流程：用户通过校园邮箱注册并验证身份 → 浏览帖子区种草或直接进交易区搜索商品 → 看到心仪商品后与卖家发起聊天协商 → 协商一致后买家下单 → 买家支付（线上模拟或线下当面）→ 约定时间和地点校内面对面交割 → 买家确认收货，交易完成 → 双方互相评价。售后环节全凭双方私下沟通解决；若协商不成，任一方可发起校内公开小法庭，由同校学生投票仲裁。

帖子引流路径：

卖家发帖分享好物 → 帖子下方挂载商品链接 → 买家浏览信息流被种草 → 点击链接跳转交易区商品页 → 进入上述交易流程。



## 项目范围

### 当前阶段实现的内容

## 后续课程演进方向

**认证授权**：Spring Security + JWT 令牌鉴权，校园邮箱验证码确保学生身份，基于角色的访问控制（学生/管理员），敏感操作二次验证。

**服务拆分**：按业务域拆分为用户服务、帖子服务、商品服务、订单服务、聊天服务、小法庭服务、管理服务，通过 Spring Cloud + Nacos 实现服务注册发现与配置中心，API 网关统一路由。

**消息系统**：WebSocket 实现一对一实时聊天和消息推送，RabbitMQ 处理异步通知（订单状态变更、帖子互动提醒、小法庭开庭通知），消息持久化保障离线消息不丢。

**事务管理**：订单创建 + 扣减库存 + 支付确认的分布式事务一致性，采用 Seata AT 模式保障；小法庭投票达阈值后自动触发裁决状态变更，需保证原子性。

**监控运维**：ELK 收集应用日志，Prometheus + Grafana 监控 JVM 指标和业务指标（订单量、帖子上报量、小法庭发起数），SkyWalking 链路追踪定位跨服务调用瓶颈，告警规则覆盖异常订单和违规内容。

**容器化部署**：Docker 容器化每个微服务，Nginx 反向代理和负载均衡，Jenkins CI/CD 自动构建部署，初期单机 Docker Compose 编排，后续视需要扩展至多节点。

## 四、目标用户

**买家**：有购买需求的学生，核心需求是搜索商品、与卖家沟通、下单支付、安全交割、交易评价。

**卖家**：有闲置物品出售的学生，核心需求是快速发布商品、管理上下架、回复咨询、处理订单。

**典型用户画像**：在校学生在开学季低价获取教材、电子产品、生活用品，日常出售闲置回血；毕业班学生在毕业季批量转手教材、宿舍用品、电瓶车等大件快速清仓；教职工偶发性转让闲置书籍、器材。
